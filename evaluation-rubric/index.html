The three-commit historical bake-off protocol

Instead of inventing synthetic prompts during a vendor trial, select three merged production commits from the past six months that required multiple human review rounds:

  1. A concurrency, retry, or state-boundary bug where existing unit tests originally passed before the incident occurred.
  2. A cross-module refactor touching at least four files with strict backward-compatibility invariants.
  3. A security or permission-boundary hardening change where subtle bypasses are easy to overlook.

Check out the parent commit prior to the human fix, provide the exact same frozen requirement specification below to each orchestrator, and blind-grade the resulting pull requests on: (a) unprompted edge-case coverage, (b) zero weakened existing tests, and (c) minutes of principal engineer review time required before merge confidence.

Copyable frozen task specification template

High-assurance orchestrators perform best when given explicit behavioral obligations and invariants rather than vague step-by-step hints. Use this specification structure across every tool in your evaluation:

benchmark-intention-template.md 
# Engineering Task Specification

## 1. Objective
Describe the observable system behavior that must hold after this change, written from the caller's perspective rather than prescribing which lines to edit.

## 2. Behavioral Obligations
- Under concurrent retries or upstream timeouts, callers must never receive stale state or leak pending handles.
- Public API signatures and wire formats in existing routes must remain backward-compatible.
- Error propagation must preserve structured cause codes for telemetry.

## 3. Explicit Non-Goals
- Do not introduce new external runtime dependencies.
- Do not modify database schema migrations or relax existing test assertions.

## 4. Acceptance Criteria
- All existing unit and integration suites pass without weakened mocks.
- At least one deterministic regression test reproduces the failure mode on the baseline commit and passes with the fix.

Enterprise security, model economics & data custody checklist

Before clearing any orchestrator for proprietary source repositories, verify four operational guarantees with security and architecture leadership:

  • Zero training & zero data retention: Confirm whether prompts, indexes, or transient diff traces are retained in US multi-tenant logs. Askus Operator executes on zero-data-retention servers in Liechtenstein and Switzerland (LI / CH) with zero training on customer code.
  • Bring-your-own model contracts: Verify that orchestration is not hardcoded to a single LLM vendor's pricing or outages, and can route across Copilot, Codex, frontier cloud APIs, or internal weights.
  • Cost-efficient token economics: Ensure the orchestrator can extract frontier-grade engineering quality from fast, economical models rather than burning maximum-tier tokens on every step.
  • Auditability: Require clear verification records so engineering leadership can audit why a change passed quality gates before merge.
